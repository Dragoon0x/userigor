▌ what it is

Most AI tools have no idea if they're getting better.

Memory journals and rule files are great until they aren't. They tell you what someone wrote down. They don't tell you whether your agent is producing more first-try-acceptable code, or less. userigor closes that loop with measurement.

Capture is automatic. Walk git history, diff each commit against its parent, and a Correction is born — before, after, language, file, agent, task. No /learn-rule commands, no rituals.

Patterns are clusters, not rules. Embeddings group corrections that look alike. The cluster centroid becomes a Pattern. Patterns earn or lose status based on data, not vibes.

Injection is pre-flight. Before the agent generates, similar patterns are scored by similarity × impact and dropped into a structured <rigor:context> block. The agent stays agnostic — Claude Code, Cursor, anything that speaks MCP.

Measurement is honest. First-try acceptance, edit-after-accept, revert rate, drift distance, and pattern coverage are computed in windows. Patterns whose injection didn't help get retired.

▌ how the loop works

Four stages, each one measurable.

The pipeline is deliberately small. Each stage has well-defined inputs, outputs, and an honest measurement attached. Nothing in the loop runs on faith.

01 Capture Diff the AI's output against what was actually committed. The result is a Correction record: before, after, file, language, agent, task description, velocity. Idempotent. Skip if identical. in git diff · out Correction
02 Cluster Embed each correction with the bundled hybrid TF-IDF + character n-gram provider (or plug in OpenAI). Form clusters with cosine similarity. Each component above min-size becomes a Pattern. in embeddings · out Pattern
03 Inject Embed the user's prompt, score every active pattern by similarity × (1 + impact), keep the top K above threshold, splice them into the prompt as a structured context block. Persisted for attribution. in prompt · out augmented prompt
04 Measure Compute first-try acceptance, edit-after-accept, revert rate, correction velocity, drift distance, pattern coverage. Compute pattern impact with vs without injection. Retire patterns that don't earn it. in history · out causal evidence
▌ metric dictionary

Six numbers you can actually defend.

These are the metrics computed by the engine, not invented for marketing. Each one has a precise definition, a clear direction, and shows up in rigor metrics, the MCP server, and the dashboard.

first_try_acceptance
↑ better
Fraction of AI outputs accepted with zero edits before commit. The headline number.
edit_after_accept
↓ better
Average lines edited after the user clicked accept but before commit. Catches the “looked good, had to fix it” failure.
revert_rate
↓ better
Fraction of corrections inverted by a later correction within seven days. Catches the “shipped, broke later” failure.
correction_velocity
↓ better
Median seconds between AI emission and final commit. Time spent correcting is time the loop is failing.
drift_distance
↓ better
Mean diff size of corrections in the window. Lower means the AI's output sits closer to what shipped.
pattern_coverage
↑ better
Fraction of corrections that fall into a known cluster. Higher means the system is recognizing recurring problems.
▌ shipping

Six packages, one monorepo.

Everything in this list is implemented, tested, and built. Each package is published to npm under its own version, with TypeScript strict, ESM, and zero deprecated subdeps.

@userigor/core engine Capture, embed, cluster, inject, measure. SQLite store, TF-IDF default embedder, optional OpenAI provider, pluggable backend interface. imports: Rigor, SqliteStore, injectContext
@userigor/cli command line The rigor binary. init, capture, backfill, embed, cluster, patterns, inject, metrics, series, prune, status, config. bin: rigor
@userigor/mcp model context protocol Stdio MCP server exposing rigor_recall, rigor_capture, rigor_cluster, rigor_metrics, rigor_patterns, rigor_pattern_detail, rigor_status. bin: rigor-mcp
@userigor/claude-code adapter SKILL.md, slash commands (rigor-recall, rigor-metrics, rigor-patterns), example MCP and PostToolUse hook configs. Drops into ~/.claude/. bin: rigor-claude-code-install
@userigor/cursor adapter Renders active patterns as .cursorrules (or modern .cursor/rules/userigor.mdc). Sorted by causal impact. bin: rigor-cursor
@userigor/dashboard local web console Single-page console at localhost. Overview, patterns with causal detail, time-series chart, status. Reads the same SQLite db. bin: rigor-dashboard
▌ install

Two commands to first signal.

Pick the surface you actually use. The CLI alone gets you the full loop. Add the MCP server when you want your agent to recall patterns pre-flight.

Just the CLI

Capture from git history, cluster, get metrics. Zero agent integration required.

# global install
npm install -g @userigor/cli

# initialize the db at ~/.rigor/
rigor init --agent claude-code

# walk recent git history, capture corrections
rigor backfill --limit 200

# form patterns, see metrics
rigor cluster
rigor metrics

With Claude Code (MCP)

Adds rigor_recall and friends as MCP tools. Plus a SKILL.md and slash commands.

# install the adapter
npm install -g @userigor/claude-code @userigor/mcp

# drop SKILL.md, slash commands, example configs
rigor-claude-code-install

# register the MCP server in ~/.claude/settings.json
# (see ~/.claude/rigor/mcp.example.json)

With Cursor

Generates a .cursorrules file from active patterns, sorted by causal impact.

npm install -g @userigor/cursor

# write .cursorrules in cwd
rigor-cursor

# or modern .cursor/rules/userigor.mdc
rigor-cursor --modern

Local dashboard

A local web console for browsing patterns, metrics, and time-series. Reads the same db.

npm install -g @userigor/dashboard

# open http://127.0.0.1:7717
rigor-dashboard
▌ design notes

Opinionated, by choice.

Local first. Everything runs against a SQLite database at ~/.rigor/data.db. The dashboard binds to 127.0.0.1. No telemetry leaves your machine unless you opt into the OpenAI embedding provider.

Agent agnostic. The MCP server speaks the standard protocol. Claude Code, Cursor with MCP, custom clients — all drop in. The Cursor adapter is just an output format for tools that don't speak MCP yet.

Pluggable embeddings. The default hybrid TF-IDF + char n-gram provider has zero external deps and is good enough for most repos. When you want stronger clustering, swap in OpenAI text-embedding-3-small with one constructor arg. The store doesn't care.

Causal evidence. A Pattern's impact_score is computed as the first-try-acceptance delta between sessions where it was injected vs sessions where it wasn't. Patterns that don't earn their keep get retired automatically by rigor prune.
